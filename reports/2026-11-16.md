## Impact on the build

**Breaking:** TMDb Helper 6.22.0 with sync.trakt 1.2.9. The provider's `identifiers/database.py` calls `self.access.connection.open()` in `is_queried()` and `get_item()`, which now raises `AttributeError: 'DatabaseAccess' object has no attribute 'connection'` (reproduced against the released 6.22.0 code). Every Trakt id lookup fails, so the For You calendar, Up Next / trakt_nextepisodes and watchlist rows come up empty or error. Devices auto-update TMDb Helper from the aggregated jurialmunkey dir, so the Shield is most likely already affected.

Checked and unaffected on the released versions:
- All 26 tmdbhelper_settings keys, both trakt_module_settings keys and the mdblist key exist in their settings.xml. sync_provider_watched / watchlist = trakt are valid catalog ids.
- All 8 `info=` routes in lists.json resolve in core or the providers.
- EpisodeItemMapper: no upstream get_params, anchor found once; the episode params patch still applies.
- `invalidate_sync=watched` still a key in sync/invalidator.py. Trakt `token` and MDbList `apikey` settings present; `TMDbHelper.TraktIsAuth` still set.
- AF3 3.5.1: skinvariables-shortcut-hubs.json and the migrate files are unchanged; every skin_settings id that existed in 3.4.22 still exists. The build's three search widgets (DefaultSearch-TMDBShows / Movies / People) are all defined in the new skinvariables-multisearch-paths.json, so the multisearch window uses them. `Search.DisableDiscover` is still referenced. Home.xml only drops 11105 from UseLocalWindowIDs and the HomeSwitcher.Search.Mode default (the build does not set it).
- SkinVariables 2.3.0 still writes `<skin>-viewtypes.json` in addon_data, so the build's viewtypes deploy holds. Resolves yesterday's AF3 watch item.
- All new floors (jurialmunkey 0.2.39, SkinVariables 2.3.0, TMDb Helper 6.22.0) resolve from the jurialmunkey omega dir that repository.aanotherworld aggregates.
- sync.mdblist 1.1.4 uses no removed API; its imports all resolve against 6.22.0.
